# Feature 6 — Eval harness

> Spec part of [docs/15-features-overview.md](../15-features-overview.md).

## Goal

Turn chat history into a regression-test suite. A user exports their `notebooklm history --json` to JSONL, declares a per-row `expected` block (citations, answer substrings), and runs `notebooklm eval run spec.yaml` to score hit-rate, recall@k, citation precision, and answer containment. Two runs are diffed with `notebooklm eval diff` to catch regressions.

## User stories

1. A user has been chatting with their "Master Brain" notebook for weeks. They export the chat to a JSONL eval set; they hand-tag the first 20 rows with `expected_citations`. They run `notebooklm eval run spec.yaml` and see hit-rate = 0.85.
2. After a `notebooklm upgrade`, they re-run the eval and `notebooklm eval diff old new` shows the two rows that newly fail.
3. A CI step runs the eval on every release candidate; a regression fails the build.
4. An agent builds a new notebook from scratch with curated sources and wants to verify the chat answers are grounded. They write a 50-row spec and run the eval.

## CLI surface

New top-level group:

```
notebooklm eval
  export [--notebook <id>] [--output <path>]   # history -> JSONL
  run <spec.yaml> [--output <report-dir>]      # the high-traffic path
  list                                         # past runs
  show <run-id>
  diff <run-id-a> <run-id-b>                   # pairwise regression
  dataset                                      # dataset introspection
    info <dataset.jsonl>
    split <dataset.jsonl> --train 0.8 --test 0.2 [--seed <n>]
```

### Dataset format (JSONL)

One row per evaluation case. Generated by `notebooklm history --json --output history.jsonl`, then optionally hand-edited to add an `expected` block.

```jsonl
{"id": "q-001", "question": "What's our incident response procedure?", "conversation_id": "c-...", "turn_number": 1, "answer": "...", "references": [{"source_id": "src-1", "citation_number": 1}], "expected": {"must_contain": ["incident response", "on-call"], "must_cite": ["src-1"], "must_not_cite": ["src-deprecated"]}}
{"id": "q-002", "question": "Compare our pricing", "conversation_id": "c-...", "turn_number": 4, "answer": "...", "references": [...], "expected": {"must_cite_any_of": [["src-2", "src-3"]]}}
```

`expected` schema:

| Field | Type | Meaning |
|---|---|---|
| `must_contain` | `[]string` | All substrings must appear in the answer. |
| `must_not_contain` | `[]string` | None of these may appear. |
| `must_cite` | `[]string` | All of these source ids must appear in `references`. |
| `must_not_cite` | `[]string` | None of these source ids may appear. |
| `must_cite_any_of` | `[][]string` | At least one of each inner list must appear. |
| `recall_at_k` | `int` + `[]string` | At least `k` of the listed source ids must appear. |

Rows without an `expected` block are skipped (they exist for record-keeping only).

### Spec format (YAML)

```yaml
version: 1
name: master-brain-regression
notebook: nb-123                # the notebook to ask against
source: dataset.jsonl           # the JSONL dataset
pass_threshold: 0.8             # overall pass rate; below this the run fails
parallel: 4                     # chat concurrency
scoring:
  weights:
    must_contain: 0.4
    must_cite: 0.4
    must_not_contain: 0.2
  per_query:
    q-001:
      weights:
        must_contain: 0.7       # override the global weight for this query
```

      "weighted": 1.0,
      "answer_preview": "The on-call rotation requires..."
    },
    {
      "id": "q-005",

Exit codes: `0` pass; `1` below threshold; `2` no rows (empty dataset); `130` SIGINT.

### `eval diff`

Prints a unified diff of two runs:

```
master-brain-regression eval-20260101-abcd → eval-20260105-efgh

Regressions (3):
  q-005   1.00 → 0.20   must_cite: missing src-1
  q-011   0.95 → 0.00   must_not_contain: "deprecated" appeared
  q-018   0.80 → 0.40   must_contain: missing "incident"

Improvements (2):
  q-002   0.55 → 0.95
  q-007   0.30 → 1.00

Net pass rate: 0.85 → 0.75
```

`--json` returns the same as a structured envelope.

## Public SDK additions

```go
type EvalDataset struct { Path string; Rows []EvalRow }
type EvalRow struct {
    ID, Question, ConversationID string
    TurnNumber int
    Answer string; References []Reference
    Expected *EvalExpected
}
type EvalExpected struct {
    MustContain, MustNotContain []string
    MustCite, MustNotCite []string
    MustCiteAnyOf [][]string
    RecallAtK *struct{ K int; Sources []string }
}

type EvalRunResult struct { RunID, Spec string; Total, Passed, Failed int; PassRate, Threshold float64; Rows []EvalRowResult }
type Eval struct{ client *Client }
func (e *Eval) Export(ctx, notebookID, outputPath string) error
func (e *Eval) Run(ctx, specPath string, opts EvalRunOptions) (*EvalRunResult, error)
func (e *Eval) List(ctx) ([]EvalRunSummary, error)
func (e *Eval) Get(ctx, runID string) (*EvalRunResult, error)
func (e *Eval) Diff(ctx, runA, runB string) (*EvalDiff, error)
```

## Data model under `~/.notebooklm/`

| Path | Format | Purpose |
|---|---|---|
| `~/.notebooklm/evals/` | dir | one folder per run |
| `~/.notebooklm/evals/<run-id>/` | dir | `spec.yaml` (committed copy), `report.json` (full results), `summary.md` (human-readable) |
| `~/.notebooklm/evals/<run-id>/per-query/` | dir | one JSON per query (full question, expected, got, scores, answer preview) |
| `~/.notebooklm/evals/index.json` | JSON | `{ runs: [...] }` |

Atomic writes per `internal/atomicio`. A run is durable from the moment the first query completes; a crash mid-run leaves the partial results on disk, marked `state: crashed`, and the user can re-run.

## Protocol implications

**No new RPC.** Every eval row runs through the existing `Chat.Ask` (with `--new` for fresh conversations, or `--continue <conversation_id>` to replay a recorded conversation). History export uses `Chat.GetHistory`. The scoring is pure client-side Go.

Cited reusable calls:

| Operation | SDK call | Python original |
|---|---|---|
| `Eval.Export` | `Chat.GetHistory` per notebook | `cli/history_cmd.py::history` → `_chat.history` |
| `Eval.Run` (per row) | `Chat.Ask(question, -n nb)` with optional `-c <conv_id>` | `cli/ask_cmd.py::ask` |

The eval runner is **stateless across the wire** — every row's answer is independent and reproducible.

## Tests

### Unit

| Test | What it asserts |
|---|---|
| `TestScoringMustContain` | Answer containing all required substrings scores 1.0; missing one scores 0.0. |
| `TestScoringMustCite` | All required source ids in `references` scores 1.0; missing one scores 0.0. |
| `TestScoringMustCiteAnyOf` | At least one from each inner list satisfied → 1.0. |
| `TestScoringWeighted` | Custom weights per query override the global weights. |
| `TestPassThreshold` | Below-threshold run reports `result: failed`, exit code 1. |
| `TestDiffRegression` | A row that worsens appears in `regressions`; one that improves appears in `improvements`. |
| `TestEmptyDataset` | An empty dataset exits 2, not 0. |
| `TestConversationReplay` | Running with `-c <conv-id>` continues the conversation; without, a fresh conversation is used. |
| `TestParallel` | `parallel: 4` against 20 rows runs exactly 4 concurrent asks. |

### Cassette

A pre-recorded `Chat.Ask` response for one row; `Eval.Run` reads the cassette; scoring reports the expected pass/fail.

### E2E

A live `Eval.Run` against a real notebook pair; assert the per-row scoring matches a hand-computed reference for at least three rows.

## Acceptance criteria

1. `notebooklm history --output history.jsonl` produces a JSONL file consumable by `Eval.Run` without modification.
2. `notebooklm eval run spec.yaml` against 20 rows finishes within the configured timeout; `--json` envelope matches the documented schema.
3. A run whose `pass_rate < pass_threshold` exits 1 with the failing rows named in the report.
4. `notebooklm eval diff a b` prints the documented regression/improvement sections; `--json` returns the structured form.
5. A row whose `expected` block is malformed fails the spec validation before any RPC is fired.
6. The eval runner reuses existing chat conversations when `conversation_id` is present, and starts fresh otherwise.
7. The MCP `eval_run` tool returns the same report as the CLI; a regression below threshold surfaces as a typed `EvalRegression` error.
