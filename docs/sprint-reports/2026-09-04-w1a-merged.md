## Post-merge integration fix

After W1a merged, `make check` on master failed with:

```
vet: internal/auth/refresh/l2_5.go:142:6: Storage redeclared in this block
```

Root cause: both T-S3-001a (L2.0) and T-S3-001b (L2.5) declared a local interface named `Storage` in the same `internal/auth/refresh` package. The agents ran in parallel and each independently picked the natural name.

Fix commit `d44457c`: rename L2.5's interface to `InlineStorage` (smaller surface; future ladder-wiring ticket T-S3-001d can unify them). 13 lines changed in `internal/auth/refresh/l2_5.go` only.

### Lessons for the next sub-wave

1. **Parallel agents in the same package need a shared naming convention.** Per-package: before dispatching 2+ parallel agents that may both declare new types, audit the file names they will create and pre-resolve type names. The S03-split-tickets.md notes "small files (one per rung)" but does not pin the type names — that should be in the next subticket batch's PR-template.
2. **Type collisions surface at merge time, not in agent QA.** Each agent's local `make check` passes in isolation. The integration test only fires on master after the squash merge. Mitigation: pre-write a `go build ./...` smoke test as a global CI step (we have `make check`, but vet did fire — the agents just ran in different worktrees so they couldn't see each other's types).
3. **The "rename Storage → InlineStorage" patch is a one-liner; the real cost was noticing the vet failure.** Carry this as a known issue for any future W2-W4 sub-wave that lands parallel PRs to the same package.
